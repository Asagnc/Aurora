# Isolated large-SAF acceptance fixture

These Kotlin templates are not an Aurora application source set. `scripts/prepare-apk-saf-fixture.py` copies them only into a previously prepared, separate `io.github.asagnc.aurora.fridaqualification` source tree, and adds one unexported Activity. The preparer rejects the production checkout and its ancestors/descendants before writing. The test is opt-in with `auroraApkSafTest=true`.

Build both debug APKs in that source copy and retain their SHA256 and `qualification-input/preparation.json`. Install them over the same isolated test identity, preserving its manager authorization. Stage the four compiled, non-local `AndroidBuildTools` archives in that identity's `cache/tool-device-inputs/<id>.archive`; independently verify their exact sizes and SHA256 on both hosts. Use raw ADB input (`exec-in`) when streaming files into `run-as`; `exec-out` is for reading. Wait for the remote SHA256 command to finish rather than interpreting ADB's exit status as remote command success.

Run `io.github.asagnc.aurora.qualification.ApkSafDeviceTest` through the isolated instrumentation target. It waits for the Activity to establish its Root connection and confirm that the SDK bundle is absent, then emits `AURORA_APK_SAF_READY`. Ask the operator to select only this run's fixed native archive through the actual system picker. Do not supply a fabricated result Intent or replace the selected URI with a FileProvider URI.

The Activity calls the unchanged production `SharedToolchainManager.installAndroidArchive`. Its companion downloads use the same explicit fixed-offline transport boundary as `ToolInstallationFixture`; production still validates every component's size, digest, layout and final publication. The local native component is read through the actual content grant. The test verifies publication, removes the exact version through the production lease-aware store, checks absence, and deletes its four staged companion archives after success.

This proves large real-SAF delivery and complete production installation/cleanup with fixed offline companions. It does not qualify official networking, persistence of URI grants, or SDK runtime execution. Main Aurora's build/export/JNI probe is recorded separately. Failures retain evidence and are not counted as successes. The 2026-11-09 device result is in `docs/evidence/0.1.40/apk-large-saf-20261109.json`.
