# 0.1.27 Root guest dispatch and durable run ledger

Implemented internally, not exposed as arbitrary Agent Linux execution. No new device qualification. 0.1.28 supersedes the provisional ownership-restoration path below with the user-approved Root batch file channel (LINUX_ROOT_FILES.md); new run capability2 prevents old services from silently using the previous scan. Linux PTY and ordinary PRoot lifecycle remain unfinished.

SQLite schema6 adds linux_runs. Its dispatch intent (exact ticket, Root PID/start/boot/epoch, owner, generation, argv/deadline) and linux_leases row commit in one transaction. One outstanding Root run per conversation prevents writable workspace reuse. Invalid generations, deleting owners or duplicate runs roll back both inserts. Foreign keys prevent releasing a lease while its run record remains. Confirmation validates protocol, run UUID, generation and stopped=true, then deletes intent and lease in one transaction. No replay on restart. Status/count use SQL queries, without parsing every ticket on normal command completion.

AIDL appends startLinuxRun/recoverLinuxRun after existing methods, preserving transaction numbers. snapshot linuxRunProtocol1 gates new calls; older Root services still support their existing capabilities. Root verifies caller UID and ticket app UID. Dispatch requires the exact current service identity. Recovery first cancels/joins the same-epoch job; another service requires old boot/PID/start identity to prove prior service gone. Existing RootCommandSession owns callbacks and cancellation. Native runner/artifact pipeline and bounded task wake locks are reused.

Root stores one-use tickets and terminal markers under resources/linux-runtime/<UUID> (Root0700), separate from installation staging. Binding a recovery intent prevents delayed starts from reusing the UUID. Native per-run startup flock and scope journal recovery reject live/ambiguous guards. Generic runner exit or Binder loss is not proof. Only a successful native recovery (verified response) plus workspace handling may publish stopped. Root journals are currently retained; future GC must preserve tombstones while the originating service epoch can still issue a delayed call. This metadata is not an authorization sandbox against arbitrary Root programs.

Writable HOME/tmp/project are conversation-local in .aurora-linux; a workspace identity and active-run marker prevent claiming an unknown directory or another run. Per-job view stays private. Current internal validation path returns nofollow file/directory ownership and minimum App access after scope exit; this is a provisional full-tree scan, not a scalability claim. Proposed replacement is Root batch file access, awaiting explicit approval. Root-created special files and full Android SELinux behavior still require device tests.

On interruption/transport loss the App retains intent and lease unless Root confirms stopped; best-effort recovery never replays argv. The Linux page and linux_environment recover_runs provide explicit recovery and counts. Delete recovery skips conversations with Linux leases, allowing application startup and unrelated cleanup to continue. After confirmation, pending deletions can resume. Existing ordinary PRoot probe leases are not treated as Root run intents.
