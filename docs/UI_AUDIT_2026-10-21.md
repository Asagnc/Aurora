# Eta、DSHA 与 Aurora 实际页面对比

记录日期：2026-10-20 至 21。用户要求先实际点击、比较 UI 和功能，再继续开发。2026-10-21 用户确认：DSHA 受 ARM64 环境阻碍的页面最后补齐，先按现有证据继续；Aurora 集中真机验收仍放最后。

本轮结论：Aurora 应保持已认可的胶囊 B，优先补完整任务观看、结果阅读和工具反馈。Eta 值得学习设备能力与权限的组织；DSH/DSHA 值得学习对话、文件、任务和插件组成工作台的方式。没有性能领先或最高缓存命中的比较数据。

模拟器重启恢复了旧快照，曾短暂显示 Aurora 0.1.6。发现后先保留数据覆盖安装哈希为 `9fbcd2e79c747266fd593cd79774dbf845ad5be15cc632ece6939b113d664c60` 的 0.1.9，再录制带 `019` 的截图。`historical-016-*` 不作为 0.1.9 证据。模拟器发生的 System UI 无响应不归因于竞品或 Aurora。

### Aurora 0.1.9 自查

重新点击主页、抽屉、设置、外观、预设/自定义配色、工具能力；核对会话菜单与空间浏览源码。既有浏览器、供应商等验收见历史文档，本轮不重记为全部新验收。

明确发现工具页还写“后台任务与终端尚未接入”，与 0.1.9 已实现前台服务不符。本轮修正文案，将已实现后台 Agent 与未实现交互式 PTY 分开，未增加新的执行架构。当前文件预览仍为对话框，Skills 仍是目录，工具状态仍以静态介绍为主；这些是体验与能力缺口。

## 我的判断与取舍

| 维度 | 值得学习的具体做法 | Aurora 的落点 |
| --- | --- | --- |
| 整体美观 | Eta 的原生层级、留白和工具卡片；DSH 的稳定侧栏与工作面板 | 保留 B 输入区与配色能力，统一页面标题、间距、行高、语义图标和选择层；避免仅为入口更换不同弹层样式 |
| 阅读 | 工作记录与最终结果有层级，细节按需展开 | Markdown、代码块/复制、链接、消息操作、自动跟随/回到底部、文件结果入口优先；长输出有界渲染 |
| 任务观看 | 一个任务能定位到会话、工具、终端和结果文件 | 已有前台任务记录继续扩展日志/产物关系；状态由运行事实产生，失败、取消、中断分别显示 |
| 终端输出 | DSH 设置明确长输出转文件；有后台 job 与会话工具目录 | Aurora 当前每流仅保存前 8 MiB、其后排空计数，不能声称完整保存；后续设计可分页读取日志和受控轮转，预算/丢弃必须明确 |
| 设备能力 | Eta 工具卡直接说明需要何种权限、支持条件和验证结果 | 建立真实能力状态与结构化不可用原因；普通和 Root 分离，不增加 Shizuku/VPN 替代路径 |
| 工具效率 | DSH 预设能组合工具、批处理和结果筛选 | 优先把已有批读/编辑/浏览器/命令结果做成可复用 Agent 工具；独立读取可并发，同一文件/页面/终端的变更串行 |
| 扩展与恢复 | DSHA 有安装、维护、备份、诊断和受限状态入口 | Skills/工具包版本固定、校验、安装恢复、任务固定依赖；运行数据与共享依赖独立，不删除会话就重复下载 |
| 配置密度 | 很多底层选项并不适合新用户第一屏 | 主流程只出现实际可用能力；代理在浏览器内，详细预算在详情；默认值经过验证，必要时显示可操作原因 |

不能直接照抄：DSHA 的庞大首装环境、实验性模块、桌面信息密度；Eta 的特定 ROM 私有接口不能当成所有 Android16 设备 API。Aurora 用原生 Compose 也不自动意味着更低内存或更快，必须用同任务、同模型、同网络测量。

缓存优化继续按协议、精确模型、实际端点/凭据路由与请求能力处理。尽量固定系统提示、工具定义与历史序列化；模式变化尽量避免无谓重排工具。切换模型/思考等级时给出基于具体供应商规则的提示，不能一律断言缓存必定清空。展示实际 cache read/write、可用时的费用与时延，不以“命中率最大”牺牲任务质量，也不能从本轮无密钥 UI 比较得出真实命中结论。

## 后续顺序与验收标准

1. **观看与阅读**：Markdown/代码/复制、跟随滚动、统一工具详情与产物入口。遵守已认可 B 布局，不再随意重做主页。长回复不能每个 token 重建全部历史，代码和网页内容不执行为 UI 指令。
2. **持续日志与终端**：在既有监督程序、任务账本和前台服务上研究 PTY/日志模型；新底层方案先比较官方实现并确认。验收取消、超时、退出码、部分输出、重连/进程死亡、输出预算，不能自动重放不确定操作。
3. **Skills/版本化工具包**：清单、哈希、版本固定、共享依赖、原子发布/失败恢复和 Agent 发现；再接 Linux/逆向/Root 抓发包/手机构建链，不能把只读目录入口当成功能完成。
4. **模型能力与缓存**：刷新官方在售目录、端点/参数能力、可重放请求夹具后再做真实 API 对照；质量、端到端时延、费用和缓存一起记录。
5. **集中真机补验**：Aurora 最新后台/Root/锁屏/省电组合、ARM64 原生工具，以及本轮受阻的 DSHA 手机聊天/插件/终端。新特权能力需要用户实际授权时及时联系，FolkPatch 使用管理器内授权。

以上是实现优先级与建议，不把未实现能力或尚未确认的新架构写成完成。页面审计不替代任务正确率、耗电、内存峰值、TTFT、工具耗时、后台恢复和跨设备基准。
